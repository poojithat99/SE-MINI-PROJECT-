## Objective

Execute the repository's complete Python `unittest` suite on the current local project and retain an auditable record. The suite includes automated unit, API, integration and regression checks; its **81 test functions are not equivalent** to the **79 planned STP test-case IDs**, which still require execution-level results.

## Method

From the repository root, using the installed dependencies:

```powershell
New-Item -ItemType Directory -Force storage\part3_test_data\results | Out-Null
python -m coverage run --branch --source=src,backend -m unittest discover -s tests -v *> storage\part3_test_data\results\unit_tests.txt
$unitExit = $LASTEXITCODE
Get-Content storage\part3_test_data\results\unit_tests.txt -Tail 20
"Unit test exit code: $unitExit"
```

**Execution source:** User-provided local PowerShell results, not a newly executed copy of the tests by the report author. Full raw console output is retained locally at `storage/part3_test_data/results/unit_tests.txt` and is not included in the repository by default.

## Scope and limits

- A passing automated test suite does **not** establish that all 79 STP catalogue cases passed.
- Manual browser/system validation, user roles, performance, two-reviewer AI evaluation, usability, and deployed AI processing need separate evidence.
- The Render Free hosted backend previously exceeded the 512 MB RAM limit during AI file processing (tracked in Issue #72). This failure is not resolved by a successful local test run.
- Frontend tests are separate from the Python run. The tester subsequently reran all six frontend Node tests locally on **1 November 2026**, and all six passed; the Vite production build succeeded (see local frontend subsection below).
- Re-run after material source changes and record the new commit identifier, date, outputs and any failures before treating this as a final submission report.
